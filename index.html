01 · Summary

The run at a glance

What changed since v1

More systems. systems were added to the of v1, on the same 200 passages and under the same translation instructions.

New judges, applied to everything. Both v1 judges were replaced, and all translations were scored again, so old and new systems are measured with one instrument.

Tiers and cost. Systems are grouped into tiers that the passage-level evidence can separate, and each system's score is set against what it cost to produce the 200 translations.

It remains a model-judge benchmark, not human MQM or post-editing adjudication. No human scored these outputs.

Safe conclusions

  • Which systems form the leading group on these passages under these two judges.
  • That two systems in different tiers differ by more than passage-to-passage noise.
  • Which systems give the highest score for what they cost.
  • That the order of the v1 systems holds under a different pair of judges.

Do not conclude

  • Human-verified translation quality.
  • That a difference between two systems in the same tier is real.
  • That a v1.1 score can be compared with a published v1 score.
  • Performance on genres or passage lengths outside this set.

03 · Value

Score against cost: the Pareto frontier

A system is on the frontier when no other system scores higher for the same money or less. Everything below and to the right of the line is matched or beaten by something cheaper. The second line is the frontier among hosted models only, leaving out the one model that runs locally at no API cost.

How to read it. The horizontal axis is logarithmic. Cost is what the provider charged to translate the passages a system completed, scaled to 200, and it excludes judging. The local model has no API cost and is drawn at the left edge. For systems that needed several attempts on some passages, the failed attempts are not counted.

Table view: every system with its cost, frontier status and the cheapest system at least as good

Cheapest at least as good names the least expensive system that costs no more and is not significantly worse on shared passages (95%). It is computed for systems scoring above 75. An empty cell means no cheaper system matches it.

05 · Diagnostics

Dimension scores and failure flags

Besides the overall score, each judge scores four dimensions and sets three flags. The table gives each system's mean dimension score over both judges, and the share of its judge scores that carry a flag. A stronger blue is a higher score.

The colour scale runs from 70 to the highest value in the table; everything below 70 has the faintest shade. The dimension scores are the judges' own sub-scores, not a recomputation from error lists. Critical failure, omission and addition are judge flags, not human error labels.

07 · Method and limits

What was done, and what limits the result

Method

  • Passages. The 200 passages of v1, unchanged: 90 from 84000-related sources, 70 from Lotsawa House and 40 locally curated expert translations.
  • Translation. Each system translated from the Tibetan source alone, under the v1 translation instructions. Reference translations were never sent.
  • Judging. Each judge read the Tibetan source and one candidate translation, with no reference translation, and returned an overall score from 0 to 100, four dimension scores, three flags and a list of errors.
  • Score. The two judges' overall scores are averaged per passage, then over passages.
  • Tiers. Systems are sorted by score. A tier is the leading system plus every system not significantly below it in a paired comparison over shared passages (95%).
  • Cost. Provider-reported generation cost for completed passages, scaled to 200. Judging cost is excluded.

Limits

  • The judges are models. They can miss source-language detail and reward fluent English. Agreement between them is not proof of correctness.
  • No context. The judges saw each passage alone. In a separate test on 40 passages, the same judges scored expert reference translations markedly higher once they were given the preceding sentences, so passages that depend on context are probably under-scored here for every system.
  • A judge scores its own family.
  • Not blind. The judges could see which system produced each translation. A blinding test on a sample moved scores by less than one point.
  • Incomplete systems. The missing passages are left out of that system's mean, not scored as zero.
  • Cost counts completed passages only. Systems that ran away on some passages cost more in practice than the figure shown.
  • One model appears twice. Under the request every system received, Gemini 4 Argon used almost no reasoning, unlike the earlier Gemini models. It was therefore also run with high reasoning effort requested, as a second entry. Every other system was run with the default request only.
